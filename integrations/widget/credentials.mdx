EthioReview issues **one API client** per integration. Each client generates linked credentials. Use the right credential for where your code runs.

## Who this is for

Anyone embedding a widget or calling partner APIs. Start here if you are unsure whether to use `pk_*` or `sk_*`.

## Credential types

| Credential | Format | Where to use |
| ---------- | ------ | ------------ |
| **Publishable key** | `pk_live_*` / `pk_test_*` | Browser embeds — React, Web Component, iframe, React Native |
| **Secret key** | `sk_live_*` / `sk_test_*` | Server-only partner API — never in client code |
| **Client ID** | `cli_*` | Internal identifier — not sent by integrators |

### Publishable key (widget embeds)

Create under **Integrations → API keys**. Pass it to the SDK as `publicKey` or `publishableKey`:

```tsx
<ReviewWidget
  baseUrl="https://api.ethioreview.com"
  publicKey="pk_live_YOUR_KEY"
  widgetId="YOUR_WIDGET_ID"
/>
```

The SDK sends it as the `X-Widget-Key` header on every public widget request.

### Secret key (server integrations)

Use `Authorization: Bearer sk_live_*` for partner API routes such as `POST /partner/reviews`. Keep secrets in environment variables on your server only.

## Dashboard clicks

| Action | Path |
| ------ | ---- |
| Create sandbox keys | **Integrations → API keys** → **SANDBOX** |
| Create production keys | **Integrations → API keys** → **PRODUCTION** |
| Link widget to client | **Integrations → Review widgets** |
| Preview sandbox | **Integrations → Sandbox test** |

## Origin allowlist

Every API client has an **allowed origins** list. Browser requests must come from a matching domain.

- Add every production, staging, and preview domain before go-live
- An empty allowlist blocks all widget traffic
- Local dev: include `http://localhost:3000` (or your dev port)

Full guide: [Allowed origins](/api-keys/allowed-origins).

## Environment matching

| Dashboard environment | Publishable key prefix | Widget environment |
| --------------------- | ---------------------- | ------------------ |
| Production | `pk_live_*` | **PRODUCTION** |
| Sandbox | `pk_test_*` | **SANDBOX** |

A sandbox key cannot resolve a production widget, and vice versa.

## One failure mode

**Rotated keys but old `pk_*` still in CMS** — after [rotate](/api-keys/rotate-revoke), update WordPress shortcodes, Shopify theme settings, and env vars in every environment.
